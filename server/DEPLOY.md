# ขึ้นเว็บบนเซิร์ฟเวอร์โรงเรียน

## สิ่งที่ต้องถามครูผู้ดูแลเซิร์ฟเวอร์ก่อน

1. เว็บจะอยู่ที่ URL อะไร เช่น `http://www.โรงเรียน.ac.th/school-info/`
   - ถ้าชื่อโฟลเดอร์ไม่ใช่ `school-info` ให้แก้บรรทัด `set "APP=school-info"` ใน `deploy.bat`
2. อัปโหลดไฟล์ด้วยวิธีไหน (คัดลอกผ่านแฟลชไดรฟ์ / FTP / แชร์โฟลเดอร์)
3. ชื่อฐานข้อมูล ชื่อผู้ใช้ และรหัสผ่าน MySQL ที่ใช้ได้ และเข้า phpMyAdmin ได้ที่ไหน
4. เซิร์ฟเวอร์เป็น Apache และอนุญาตไฟล์ `.htaccess` หรือไม่ (`AllowOverride All` และเปิด `mod_rewrite`)

## ติดตั้งครั้งแรก

1. **สร้างชุดไฟล์:** ดับเบิลคลิก `deploy.bat` ในโฟลเดอร์โปรเจกต์ แล้วรอจนขึ้น "เสร็จแล้ว"
   - `deploy\school-info\` คือหน้าเว็บ + API อัปโหลดทั้งโฟลเดอร์นี้
   - `deploy\database\install.sql` คือไฟล์สร้างฐานข้อมูล
2. **ฐานข้อมูล:** ใน phpMyAdmin ของเซิร์ฟเวอร์
   1. สร้างฐานข้อมูล ตั้ง Collation เป็น `utf8mb4_unicode_ci` (ถ้าครูสร้างไว้ให้แล้ว ข้ามได้)
   2. คลิกที่ฐานข้อมูลนั้น → แท็บ Import → เลือก `install.sql` → Import
   3. ถ้าต้องการข้อมูลย้อนหลังปีการศึกษา 2566–2568 ให้ Import ตามลำดับ: `historical-2566-2568.sql` → `five-aspects-content-2566-2568.sql` → `cleanup-duplicate-topics.sql`
      ไฟล์ข้อมูลย้อนหลังนำเข้าซ้ำได้โดยไม่สร้างหัวข้อซ้ำ
   4. **ไม่ต้อง** import ไฟล์ข้อมูลตัวอย่าง (sample-data)
3. **อัปโหลด:** คัดลอกโฟลเดอร์ `deploy\school-info` ไปวางในที่เก็บเว็บของเซิร์ฟเวอร์ (เช่น `htdocs\` หรือ `public_html\`)
   - ต้องมีไฟล์ซ่อน `.htaccess` ติดไปด้วย 3 ไฟล์ (ที่โฟลเดอร์หลัก, `uploads` และ `raw-uploads`)
4. **ตั้งค่าฐานข้อมูล:** บนเซิร์ฟเวอร์ ในโฟลเดอร์ `api\`
   คัดลอก `config.example.php` เป็น `config.php` แล้วแก้ 4 บรรทัด `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS`
   - ระบบสำรองอัตโนมัติก่อนกู้คืนไว้ภายนอกโฟลเดอร์เว็บโดยอัตโนมัติ ถ้าโฮสต์เขียนตำแหน่งนั้นไม่ได้ ให้กำหนด `BACKUP_DIR` ใน `config.php` เป็นโฟลเดอร์ที่ PHP เขียนได้และอยู่นอก `htdocs/public_html`
5. **ตรวจความพร้อม:** เปิด `http://…/school-info/api/check.php`
   ต้องขึ้น ✅ ทุกข้อ ยกเว้น "สร้างผู้ดูแลระบบแล้ว" (ทำในข้อถัดไป) ถ้ามี ❌ ให้ทำตามคำแนะนำสีส้ม
6. **สร้างผู้ดูแลระบบทันที:** เปิด `http://…/school-info/login` จะขึ้นหน้า "ตั้งค่าครั้งแรก"
   ⚠ ทำทันทีหลังอัปโหลด เพราะหน้านี้เปิดให้ทุกคนจนกว่าจะมีผู้ดูแลคนแรก
7. แท็บ "ผู้ใช้" → สร้างบัญชีให้ 4 ฝ่าย, แท็บ "ปีการศึกษา" → ตั้งปีปัจจุบัน
8. ลองกด F5 ในหน้าเล่ม ถ้าขึ้น 404 แปลว่าเซิร์ฟเวอร์ไม่อ่าน `.htaccess` ให้ครูผู้ดูแลเปิด `AllowOverride All` และ `mod_rewrite`

## คู่มือ Deploy สำหรับการอัปเดตครั้งต่อไป

คู่มือนี้ใช้เมื่อเว็บไซต์ติดตั้งบนเซิร์ฟเวอร์แล้ว และต้องการนำโค้ดหรือหัวข้อฐานข้อมูลรุ่นใหม่ขึ้นไปแทนรุ่นเดิม โดยทำงานผ่าน WinSCP และไฟล์ `.bat` ที่อยู่ในโฟลเดอร์หลักของโครงการ

### ค่าที่ระบบใช้อยู่

- โฟลเดอร์โครงการในเครื่อง: `C:\Users\Admin\Desktop\school-info\school-info-web`
- WinSCP saved session: `school-server`
- เซิร์ฟเวอร์: `192.168.80.250`
- โฟลเดอร์เว็บบนเซิร์ฟเวอร์: `/opt/lampp/htdocs/school-info`
- โฟลเดอร์สำรองบนเซิร์ฟเวอร์: `/opt/lampp/school-info-backups`
- URL ของเว็บใช้ base href: `/school-info/`

หากที่อยู่เซิร์ฟเวอร์ โฟลเดอร์ หรือ URL เปลี่ยน ต้องแก้ `deploy-school.ps1` และค่า `APP` ใน `deploy.bat` ก่อน ห้ามใช้ค่าปัจจุบันกับเซิร์ฟเวอร์คนละเครื่องโดยไม่ตรวจสอบ

### สิ่งที่ต้องพร้อมก่อนเริ่ม

1. เครื่องต้องเชื่อมต่อเครือข่ายโรงเรียน หรือเครือข่ายที่เข้าถึง `192.168.80.250` ได้
2. ติดตั้ง WinSCP และต้องมี saved session ชื่อ `school-server` ที่เข้าสู่ระบบได้
3. ปิดงานแก้ไขโค้ดให้เรียบร้อย และทดสอบเว็บในเครื่องก่อน
4. ตรวจว่า Apache และ MySQL บนเซิร์ฟเวอร์ทำงานอยู่
5. เลือกช่วงเวลาที่มีผู้ใช้งานน้อย เพราะระหว่าง migration และเปลี่ยนไฟล์อาจมีช่วงสั้น ๆ ที่ข้อมูลกับโค้ดเป็นคนละรุ่น

### ขั้นที่ 1: ตรวจสถานะเซิร์ฟเวอร์

ดับเบิลคลิก `deploy-inspect.bat`

สคริปต์จะเชื่อมต่อเซิร์ฟเวอร์และอ่านสถานะฐานข้อมูล เช่น จำนวนหัวข้อ จำนวน records โครงสร้างที่จำเป็น และปีการศึกษา โดยไม่ Build ไม่อัปโหลด และไม่แก้ฐานข้อมูล

เมื่อสำเร็จต้องเห็นข้อความ:

```text
PREFLIGHT=...
Server inspection completed. No server files or database rows were changed.
```

ถ้าขึ้นว่าเชื่อมต่อไม่ได้ ให้ตรวจเครือข่าย เปิด WinSCP แล้วลอง Login ด้วย `school-server` ก่อน อย่าเริ่ม Upload จนกว่า Inspect จะผ่าน

### ขั้นที่ 2: Build และ Preview

ดับเบิลคลิก `deploy-preview.bat`

สคริปต์จะทำงานดังนี้:

1. Build Angular ด้วย base href `/school-info/`
2. สร้างชุดเว็บไว้ใน `deploy\school-info`
3. คัดลอก SQL และเอกสารไว้ใน `deploy\database`
4. เปรียบเทียบชุดในเครื่องกับเว็บบนเซิร์ฟเวอร์ผ่าน WinSCP
5. ตรวจว่าสามารถสร้างชุดข้อมูล Local ได้ และเปรียบเทียบรูปใน Local กับ `uploads` บนเซิร์ฟเวอร์
6. แสดงรายการ `Differences found` แต่ยังไม่อัปโหลด

ข้อความ `Local file ... newer than remote file` หมายถึงไฟล์นั้นจะถูกอัปเดต ไม่ใช่ข้อผิดพลาด

เมื่อสำเร็จต้องเห็นข้อความทั้งสองส่วน:

```text
===== BUILD COMPLETED =====
Preview completed. No server files were changed.
```

ถ้าขึ้น `BUILD FAILED`, `WinSCP failed` หรือมีข้อความ Error ให้หยุดแก้ปัญหาก่อน ขั้น Preview ไม่ควรเปลี่ยนไฟล์หรือข้อมูลบนเซิร์ฟเวอร์

### ขั้นที่ 3: สำรองอย่างเดียวเมื่อจำเป็น

ถ้าต้องการทดสอบระบบสำรองก่อน Deploy ให้ดับเบิลคลิก `deploy-backup.bat` แล้วพิมพ์ตัวพิมพ์ใหญ่:

```text
BACKUP
```

ระบบจะสร้างสองส่วนใน `/opt/lampp/school-info-backups`:

- ชุดสำรองข้อมูลของระบบ ซึ่งรวมข้อมูลฐานข้อมูลและไฟล์ที่ระบบสำรองรองรับ
- ไฟล์ `.tar.gz` สำรองโค้ดเว็บไซต์เดิมก่อน Deploy

เมื่อสำเร็จต้องเห็น `DATA_BACKUP=...`, `CODE_BACKUP=...` และ `Server backup completed and verified.` ขั้นตอนนี้ไม่อัปโหลดเว็บ

### ขั้นที่ 4: Deploy จริง

ทำขั้นนี้เมื่อ Inspect และ Preview ผ่านแล้วเท่านั้น

1. ดับเบิลคลิก `deploy-upload.bat`
2. อ่านคำเตือนบนหน้าจอ
3. พิมพ์ตัวพิมพ์ใหญ่ `DEPLOY` แล้วกด Enter
4. รอจนสคริปต์ทำงานจบ ห้ามปิดหน้าต่าง ปิดเครื่อง หรือตัดเครือข่ายกลางทาง

สคริปต์จะทำตามลำดับนี้:

1. Build Angular และจัดชุด Deploy ใหม่
2. สร้างชุดสำรองข้อมูลบนเซิร์ฟเวอร์และตรวจว่าไฟล์มีอยู่จริง
3. สำรองโค้ดเว็บไซต์เดิมเป็น `.tar.gz` และตรวจว่าไฟล์ไม่ว่าง
4. อัปโหลด SQL ชั่วคราวไปยัง `/tmp` บนเซิร์ฟเวอร์
5. รันเฉพาะ SQL ที่ระบุใน `deploy-migrations.txt` ตามลำดับ
6. ตรวจผล migration เช่น จำนวนหัวข้อบทที่ 1 และห้าหัวข้อใหม่
7. เมื่อทุกอย่างผ่าน จึงอัปโหลดไฟล์ Angular และ PHP ที่เปลี่ยน
8. ส่งรูปจาก Local เข้า `uploads` เฉพาะไฟล์ที่เพิ่มหรือแตกต่าง โดยไม่ลบรูปเดิมบนเซิร์ฟเวอร์
9. รวมข้อมูลที่กรอกผ่านหน้าเว็บ Local เข้าฐานเซิร์ฟเวอร์ โดยจับคู่จากฝ่าย + ชื่อหัวข้อ + ปีการศึกษา
10. ลบ SQL และไฟล์ข้อมูลชั่วคราวออกจาก `/tmp`

การรวมข้อมูล Local จะเพิ่มรายการที่ยังไม่มี และอัปเดตเฉพาะเมื่อเวลาแก้ไขของ Local ใหม่กว่า หากข้อมูลบนเซิร์ฟเวอร์ใหม่กว่าจะเก็บของเซิร์ฟเวอร์ไว้และรายงานเป็น `server_newer` การลบข้อมูลใน Local จะไม่ตามไปลบบนเซิร์ฟเวอร์

ระบบจดชื่อ Migration ที่ทำสำเร็จในตาราง `deploy_migrations` และจะข้ามไฟล์เดิมในการ Deploy ครั้งถัดไป เพื่อไม่ให้ข้อมูลที่ผู้ใช้แก้ภายหลังถูก SQL เก่าเขียนทับ หากการสำรองหรือ migration ไม่ผ่าน สคริปต์จะหยุดก่อนอัปโหลดโค้ด

เมื่อ Deploy สำเร็จต้องเห็นข้อความ:

```text
MIGRATION_OK=...
MIGRATION_SKIPPED=...
MIGRATION_VERIFY_OK ...
LOCAL_SYNC_IMPORT inserted=... updated=... unchanged=... server_newer=...
Server backup completed, then website/API upload and local data merge completed.
Listed database migrations were applied and verified before the code upload.
```

### ไฟล์และข้อมูลที่สคริปต์ป้องกันไว้

การ Deploy จะไม่ลบไฟล์บนเซิร์ฟเวอร์ และไม่เขียนทับสิ่งต่อไปนี้:

- `api/config.php` ซึ่งเก็บค่าฐานข้อมูลของเซิร์ฟเวอร์
- `uploads` จะรับเฉพาะรูป Local ที่เพิ่มหรือแตกต่าง และจะไม่ลบรูปเดิมบนเซิร์ฟเวอร์
- `raw-uploads` ซึ่งเก็บเอกสารข้อมูลดิบ
- `backups` ภายในโฟลเดอร์เว็บ
- ชุดสำรองใน `/opt/lampp/school-info-backups`

### ขั้นที่ 5: ตรวจหลัง Deploy

1. เปิดหน้าแรกของระบบและกด `Ctrl+F5` เพื่อไม่ใช้ไฟล์ cache เดิม
2. เปิดเล่มปี 2566, 2567, 2568 และ 2569 แล้วตรวจสารบัญ ข้อมูล ตารางและกราฟ
3. เข้าสู่ระบบผู้ดูแล แล้วตรวจหน้าจัดการข้อมูลและปุ่มข้อมูลดิบ
4. เปิด `/school-info/api/check.php` และตรวจรายการสำคัญให้เป็นเครื่องหมายถูก
5. ดับเบิลคลิก `deploy-inspect.bat` อีกครั้ง เพื่อดูจำนวนหัวข้อและ records หลัง Deploy
6. หากทุกอย่างปกติ ให้จดวันที่ Deploy และเก็บ log ใน `deploy-logs`

### ถ้า Deploy ผิดพลาด

- ถ้าล้มเหลวก่อนอัปโหลดโค้ด: อ่านบรรทัด Error และไฟล์ log ที่แสดงท้ายหน้าต่าง โดยทั่วไปเว็บเดิมยังอยู่
- ถ้าหน้าเว็บเก่าแสดงค้าง: กด `Ctrl+F5` หรือล้าง cache เบราว์เซอร์
- ถ้าหน้าเว็บขึ้นแต่ไม่มีข้อมูล: ตรวจ `api/config.php`, MySQL และเรียก `api/check.php`
- ถ้าโค้ดใหม่มีปัญหา: อย่าวางไฟล์อื่นทับทันที ให้ใช้ชุด `site-before-deploy-วันเวลา.tar.gz` จาก `/opt/lampp/school-info-backups` คืนโค้ดเดิม
- ถ้าข้อมูลผิดหลัง migration: ใช้ชุดสำรองข้อมูลที่สร้างก่อน Deploy ผ่านหน้าสำรองและกู้คืน หรือให้ผู้ดูแลเซิร์ฟเวอร์กู้คืน ห้าม Import `install.sql` ทับฐานจริง

ควรให้ผู้ดูแลเซิร์ฟเวอร์ช่วยกู้คืนหากไม่แน่ใจ เพราะการกู้คืนจะเขียนทับข้อมูลปัจจุบัน

### การเพิ่ม migration ในอนาคต

1. สร้างไฟล์ SQL ที่นำเข้าซ้ำได้โดยไม่เกิดข้อมูลซ้ำไว้ใน `server\database`
2. `deploy.bat` จะคัดลอก SQL ทุกไฟล์เข้าแพ็กเกจให้อัตโนมัติ
3. เพิ่มชื่อไฟล์ลงท้าย `deploy-migrations.txt` ตามลำดับที่ต้องรัน
4. ทดสอบ SQL กับฐานข้อมูลในเครื่องและสำรองฐานข้อมูลก่อนเสมอ
5. **ห้าม** ใส่ `install.sql`, ไฟล์ข้อมูลตัวอย่าง หรือไฟล์ที่ล้างฐานข้อมูลลงใน `deploy-migrations.txt`

### ไฟล์ log

ทุกครั้งที่ Inspect, Preview, Backup หรือ Upload ทำงาน จะมี log ในโฟลเดอร์ `deploy-logs` ชื่อไฟล์ประกอบด้วยโหมดและวันเวลา เช่น:

```text
winscp-preview-20261111-083549.log
winscp-upload-YYYYMMDD-HHMMSS.log
```

ถ้าเกิดปัญหา ให้เก็บหน้าจอ Error และ log ครั้งล่าสุดไว้ตรวจสอบก่อนลองซ้ำ

### ดึงข้อมูลจาก Server กลับมา Local

ระบบนี้แยกจาก Deploy และไม่แก้ข้อมูลบนเซิร์ฟเวอร์

1. ดับเบิลคลิก `sync-server-preview.bat` เพื่อดาวน์โหลด Snapshot ชั่วคราวและดูจำนวนข้อมูลที่จะเพิ่ม/อัปเดต โดยยังไม่แก้ฐาน Local
2. เมื่อตรวจรายการแล้ว ให้ดับเบิลคลิก `sync-server-to-local.bat`
3. ระบบจะแสดง Preview อีกครั้ง ให้พิมพ์ `PULL` เพื่อยืนยัน
4. ระบบสำรองฐาน Local อัตโนมัติ ดาวน์โหลดรูปและไฟล์ข้อมูลดิบที่ยังไม่มีโดยไม่ลบไฟล์เดิม แล้วรวม records และรายการข้อมูลดิบจากเซิร์ฟเวอร์

ถ้าข้อมูล Local ที่ผู้ใช้แก้มีเวลาใหม่กว่า ระบบจะเก็บ Local ไว้ การลบจากเซิร์ฟเวอร์จะไม่ลบตามใน Local ระบบนี้รวมเอกสารข้อมูลดิบ PDF/Word/Excel แล้ว แต่ยังไม่ดึงหัวข้อหรือผู้ใช้

## ห้ามทำ

- ห้ามเอา `config.php` ของเครื่องตัวเองขึ้นเซิร์ฟเวอร์ หรือขึ้น git
- ห้ามลบหรือวางทับโฟลเดอร์ `uploads` บนเซิร์ฟเวอร์ด้วยตนเอง ให้ระบบ Deploy ซิงก์แบบไม่ลบไฟล์เดิม
- ห้ามลบโฟลเดอร์ `raw-uploads` บนเซิร์ฟเวอร์ (เอกสารข้อมูลดิบของทุกฝ่ายอยู่ในนั้น)
- ห้าม import ข้อมูลตัวอย่างบนเซิร์ฟเวอร์จริง
